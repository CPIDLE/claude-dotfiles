# Auto Run — 自主執行 + 事後 redteam

opt-in 的單次修飾詞：這次任務不停下來問「該怎麼做」，卡點升級給獨立 subagent 頂替判斷；完成後跑一次 redteam review，發現的問題自動修正。取代每次手打那一長串話。

## 觸發

- `/auto-run <任務描述>` — 全新任務
- `/auto-run`（不帶描述，接續進行中的任務）— 剩下的部分改用本模式

## 執行方式

正常走既有 Plan-Execute Workflow，核准 Plan 後，本次任務的「該怎麼做」判斷不再停下來問使用者：

- 能自己判斷就判斷，繼續往下做
- 卡住 / 不確定 → 派一個獨立 subagent（`model: opus`，頂替使用者判斷，不可用 haiku）：
  - 給的素材：任務目標、卡點描述、已經試過的選項
  - 決策空間：(a) 選方案繼續 (b) 判斷這其實超出任務範圍，該問使用者 (c) 放棄某步驟但不影響整體目標
  - (b) → 才用 `AskUserQuestion` 問使用者；(a)/(c) 不問，記下理由繼續
- **唯一不可仲裁的紅線**：全域 CLAUDE.md「Plan-Execute Workflow」的「未核准的破壞性操作」這條 STOP 條件——一律照常停下問使用者，不因本指令鬆動

## 完成後

1. 跑一次 `/pm-review` deep（其 Step 2 審核 subagent 要求用 `model: opus`），並覆寫兩處原生會中斷問使用者的點：
   - Step 0 事實層污染（⚠️/❌）→ 直接升級問使用者，不派仲裁 subagent 過（事實完整性問題不該讓 subagent 判斷要不要蓋過去）
   - Step 3 🚫 REJECT → 不問，直接走下一點自動修正
2. 🔴/🟠 發現 → 自動修正，不再問；🟡 只列出來不動手
3. 有修正 → 跑一次驗證（比照 Coding Discipline：有對應 test 跑該檔、沒有跑 suite、無 test 設定則跳過），不做第二輪重審
4. 總評維持 review 當下給的結果，不因修完而自行改判成 ✅

## 結尾摘要

```
🤖 完成
✅ 完成項目：<列點>
⏭️ 跳過步驟：N（仲裁判 (c)，逐項列出理由）
🧭 仲裁次數：N
🔧 自動修正：N 項（🔴 N / 🟠 N）
⚠️ 升級詢問：N 次（原因：<簡述>）
```

---

## 注意事項

- 所有輸出使用繁體中文
- 仲裁 / 審核 subagent 一律 `model: opus`
- 破壞性操作永遠不可仲裁，判不出來一律當作破壞性
