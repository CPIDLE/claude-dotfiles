# Grill Me — 動工前逐題逼問

動手前針對一個計畫 / 設計 / 決策發動逐題訪談：走決策樹、一次一題、每題附建議答案，達成共識前不動手。把沒想透的 idea 逼清楚、隱藏決策攤開、漏洞問出來。

> 源自 Matt Pocock 的 `grill-me` / `grilling`。跟 `/pm-review`、`/rt-fact`（產出後審核）互補，補的是**動工前 sharpen plan**。

## 觸發

`/grill-me [主題]`，手動為主。無主題 → 盤問「當前對話 / 最近計畫」，開場一句話確認標的。

## 核心規則

1. **開場預排決策樹**。查完事實後，把要問的決策排成內部佇列（cache），標好上游依賴。這是「快走」前提，不必每題現想。
2. **一次一題，等回饋才問下一題**。禁止一次丟多題（含 AskUserQuestion 一次只放一 question）。逐題問是為了在顯示下一題前先看到答案有沒有偏離。
3. **預設快走、偏離才重算**（核心）：
   - 答**預設選項之一**（含建議）→ 直接推進佇列下一題，**不重推**（一路點建議跟原本一樣快）。
   - 答 **`Other` / 開放式** → 丟掉剩餘佇列、據此重新產生後續，一句話說明調整（例：「你剛說要支援離線，我把快取策略換成問衝突解決」）。
4. **事實自己查、只問決策**。答案在檔案裡（實作、設定、依賴）→ cc 自己 Grep / Read；答案在使用者腦裡（取捨、方向）→ 才問。
5. **每題附建議答案**：選擇題用 AskUserQuestion 單題，建議選項排第一 + 標「（建議）」，留 `Other`；開放題用純文字 + 附建議。
6. **達成共識前不動手**：不寫 code、不改檔。

## 收尾

使用者說「夠了 / 可以了」→ 印**決策摘要**（決策清單各自結論 + 未決 / 風險），只印螢幕不寫檔，末問一句「要不要接 `/to-spec` 寫成 spec / 落地成 plan / 交給實作？」

## 反模式

- ❌ 一口氣把多題送出（佇列是內部 cache）。
- ❌ 都選預設卻每題慢慢重推。
- ❌ 答 `Other` 卻照原佇列問下去、沒重算。
- ❌ 拿可查的事實問使用者 / 每題不給建議 / 沒共識就動手。
