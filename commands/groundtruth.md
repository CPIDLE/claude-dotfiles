# Groundtruth — 事實基礎維護

獨立指令，隨時可用，不需先進 `/pm` 工作流。維護 `GROUNDTRUTH.md`——記錄「現在確定的事實是什麼」，正文/簡報/任何衍生文件都從這份檔案取值，避免多份草稿各自對不齊、事後查不到某句話的根據。

> 設計來源：`.tips/A11-groundtruth-index.md`。跟 `/rt-fact`（事實基礎層紅隊）解的是同一類問題的兩端——`/rt-fact` 是審完之後抓污染，`/groundtruth` 是一開始就別讓污染有機會發生。

## 使用時機

- 專案內有會不斷補充/修正的事實型資訊（規格數字、報告結論、提案交期等）
- 正文常改了 A 段忘記同步 B 段、或存了多個草稿分不清哪個才是真的
- **不適用**：一般程式碼 repo（沒有持續變動的「事實」可記）。不會被 `/pm new` 自動 scaffold，只在使用者主動執行本指令時才建立。

## 標準規格

**檔名**：固定 `GROUNDTRUTH.md`，放在專案根目錄（跟 `INDEX.md` 平級）。

**格式**：

```markdown
# GROUNDTRUTH — <主題>

## YYYY-MM-DD
- <事實敘述>（依據：<來源>）

## YYYY-MM-DD（更新）
- <事實敘述，取代前版>（依據：<來源>，取代 YYYY-MM-DD 版本）
```

- 每條事實**應該**帶「依據」：會議記錄、email、文件連結、口頭確認等來源
- 事實變動 → **新增區段**，不覆寫舊區段；標注「取代 YYYY-MM-DD 版本」讓稽核軌跡完整
- 沒有來源時仍可記錄，但標 `⚠️ 待確認來源`，不擋流程

## 行為

### 無參數 `/groundtruth`

1. 檢查當前目錄有無 `GROUNDTRUTH.md`
2. **不存在** → 若無法從上下文推斷主題，先問使用者主題是什麼；建立含表頭的新檔，寫入今天日期的第一個區段
3. **已存在** → 進入更新模式：
   - 詢問「這次有什麼新資訊/變動」（或使用者已在對話中提供，直接擷取）
   - 新增一個帶今天日期戳的區段
   - 新事實與既有事實衝突 → 標注取代關係，**不刪除**舊區段
4. 完成後輸出一行：`📌 GROUNDTRUTH.md 已更新（N 條新事實，主題：<主題>）`

### `/groundtruth show`

唯讀，只顯示目前 `GROUNDTRUTH.md` 全文，不做任何修改。無檔案 → 提醒 `💡 尚未建立，使用 /groundtruth 建立`。

## 跟其他機制的關係

- **`/pm-bye`**：Step 1.6 做新鮮度檢查（GROUNDTRUTH 太久沒更新但其他文件一直在改 → 提醒），不強制、不自動改檔
- **`/rt-fact`**：`GROUNDTRUTH.md` 可視為輔助來源（有日期戳 + 主動維護），但仍需每條有「依據」才算數；沒依據的條目 rt-fact 審查時視同一般宣稱，照樣要溯源

## 注意事項

- 不自動建立在程式碼 repo 根目錄——只在使用者主動執行本指令時才產生
- 所有輸出使用繁體中文
