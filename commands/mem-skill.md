# Mem Skill — 針對需求手動搜尋 docs/ 靜態 SOP

`docs/` 裡放的是跟 skill 同樣知識密度的靜態內容（SOP、schema、查詢方法），只是不掛載進 skill 清單、不常駐 context——deploy 後在 `~/.claude/docs/`，這是固定路徑，跟目前在哪個專案無關。但因為不常駐，語意連結只能靠這個指令手動觸發全文搜尋。

不依賴 memory（memory 是 per-project 的，出了寫入當下的專案就看不到，不適合放跨專案知識）也不依賴 CLAUDE.md——`docs/` 本身就是這套機制的唯一依據。

## 用法

```
/mem-skill <你要查的需求，例如「LINE 訊息怎麼抓」「影片轉文章」「ascii-align 對齊規則」>
```

無參數 → 反問使用者要查什麼，不要瞎猜。

## 執行

1. 從輸入取出需求描述，列出關鍵字，並做合理同義詞展開（例如「LINE 訊息」也要涵蓋「群組記錄」「聊天記錄」；「影片轉文章」也涵蓋「YouTube 筆記」「圖文報告」）
2. `Grep` 對 `~/.claude/docs/*.md`（本文全文搜尋，不只是檔名或標題）
3. 每個命中的檔案，讀開頭摘要判斷是否真的相關，過濾掉關鍵字巧合但語意無關的
4. 輸出結果：
   ```
   🔍「<需求>」相關的 docs/ 靜態 SOP：
   1. [檔名](docs/file.md) — 一句話說明為何相關
   2. ...
   ```
   0 筆命中 → 明講「沒找到相關內容」，不要硬湊一個勉強沾邊的結果充數
5. 使用者確認要用哪筆後，才把完整內容 `Read` 進來套用到目前任務（若該 SOP 有附帶腳本，如 `docs/video-to-article-sop/scripts/`，一併告知路徑）

## 邊界

- 這是**手動觸發**的搜尋，`docs/` 本身平常不會自動出現在 context 裡——沒被要求就不主動搜
- `docs/` 混了設計文件跟靜態 SOP，搜到 design doc（如 `plugins.md`）也正常，不用特別排除
